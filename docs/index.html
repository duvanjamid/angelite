Inicio rápido

Un solo <script>. Todo lo que ves en esta página se ejecuta con el código que aparece debajo de cada demo.

<div id="app"></div>
<script src="angelite-lite.min.js"></script>
<script>
  const { signal, component, mount } = AngeLite;

  class App {
    count = signal(0);
    inc() { this.count.update(n => n + 1); }
  }

  component(App, {
    template: `<button (click)="inc()">Clicks: {{ count() }}</button>`
  });

  mount(App, document.getElementById('app'));
</script>

Con npm: npm i @duvanjamid/angelite y import { signal, component, mount } from '@duvanjamid/angelite/lite'.

Señales

El estado vive en signal(). Al leer una señal dentro de una plantilla, esa parte concreta del DOM se suscribe sola: cuando la señal cambia, solo se actualiza ese nodo de texto, atributo o bloque. No hay árbol virtual ni ciclo de detección de cambios.

  • signal(v) – valor escribible: s(), s.set(x), s.update(fn)
  • computed(fn) – derivada, perezosa y cacheada
  • effect(fn) – efecto secundario; devuelve una función para detenerlo

Las actualizaciones se agrupan en un microtask: varios set() seguidos provocan un único repintado.

Plantillas

SintaxisQué hace
{{ expr }}Interpolación. Siempre texto: nunca se interpreta como HTML.
[prop]="expr"Enlaza una propiedad del DOM (o un input() de un componente hijo).
[class.x] · [style.width.px] · [attr.x]Clases, estilos (en kebab-case) y atributos.

Las expresiones las ejecuta un intérprete propio (sin eval): soporta operadores, ternario, ?., ??, índices y llamadas a métodos.

Control de flujo

La misma sintaxis de bloques que Angular 17+. @for reutiliza los nodos del DOM según track, así que reordenar no recrea elementos.

Variables disponibles dentro de @for: $index, $count, $first, $last, $even, $odd.

Formularios

Formularios reactivos

FormControl, FormGroup y FormArray (@duvanjamid/angelite/lite/forms) guardan su estado en señales: value, errors, valid, touched y dirty. Como value es una señal escribible, se enlaza con [(ngModel)]. Un validador es (valor) => null | { clave: detalle }; vienen required, minLength, maxLength, min, max, pattern, email y matches.

Componentes

Un componente es una clase + component(Clase, { selector, template, imports }). Los inputs son input() (una señal escribible), los outputs son output(), y <ng-content> proyecta el contenido. Los hooks ngOnInit y ngOnDestroy funcionan como en Angular.

En HTML las etiquetas personalizadas no se pueden auto-cerrar: escribe siempre <ui-card></ui-card>.

Slots con nombre

Además del <ng-content> por defecto, un componente puede tener zonas con nombre: <ng-content select="titulo"> recibe los hijos que lleven slot="titulo". Lo que no lleva slot va a la zona por defecto. El contenido se evalúa en el ámbito del padre y sigue siendo reactivo.

Portales

<ng-portal to="#destino"> pinta su contenido dentro de otro elemento (por defecto document.body) pero lo mantiene en el ámbito del componente: sirve para modales, menús y tooltips que no deben quedar atrapados por un overflow o un z-index. Se limpia solo al destruir el bloque.

Carga diferida con @defer

@defer no renderiza el bloque hasta que se cumple un disparador, y mientras tanto muestra @placeholder. Disparadores: on idle (por defecto), on viewport, on interaction, on hover, on timer(2s), on immediate y when expr. Se pueden combinar con ;. Para dividir el código de una página entera usa load: () => import(…) en el router.

Referencias a elementos

Marca un elemento con #nombre y recíbelo con viewChild('nombre'): una señal con el elemento (o la instancia del componente, si lo pones en una etiqueta de componente) que vuelve a null cuando sale del DOM.

Errores controlados

Si un componente define ngOnError(error, dónde), recibe los errores de sus bindings y handlers y los del contenido que le proyectan. Con eso se hace un límite de error: muestra una alternativa en lugar de dejar un hueco. Sin ngOnError el error se registra en la consola y el resto de la vista sigue funcionando. (No captura errores del constructor ni de ngOnInit.)

Cliente HTTP y datos

createHttp() (@duvanjamid/angelite/lite/http) es un cliente sobre fetch con URL base, parámetros, JSON automático, timeout, cancelación con AbortSignal e interceptores (petición, next) => respuesta (como los de Angular, en cadena). Las respuestas que no son 2xx lanzan HttpError con status y data; retry(n) reintenta errores de red y 5xx. resource(() => …) guarda data, loading y error en señales, vuelve a cargar cuando cambia una señal que lea, e ignora las respuestas tardías de peticiones antiguas.

Internacionalización

createI18n() (@duvanjamid/angelite/lite/i18n) tiene un idioma activo en una señal: cualquier plantilla que llame a t() se repinta al cambiarlo. Soporta parámetros {nombre}, plurales (Intl.PluralRules: claves one, other…), idiomas regionales con respaldo (es-MX → es → idioma por defecto), carga perezosa con load() y formatos de número, fecha y tiempo relativo. installPipes() añade los pipes t, num y date. Los mensajes son texto: nunca se interpretan como HTML.

Animaciones de entrada y salida

Con animate.enter="clase" y animate.leave="clase" (módulo animate, incluido en el bundle completo) un elemento recibe esa clase CSS al crearse, y al desaparecer de un @if o un @for se queda en el DOM hasta que termina su animación o transición (con un tope de seguridad). Con prefers-reduced-motion no hay animación. Es lo mínimo para entradas y salidas; no hay transiciones entre rutas ni animación de reordenado (FLIP).

Renderizado en servidor

@duvanjamid/angelite/tools/ssr.mjs renderiza un componente en Node (con jsdom, que ya es una dependencia de build): no hay una segunda implementación que mantener, la salida es la misma que construiría el navegador, con la misma sanitización de URL y escapado. En el cliente, hydrate() sustituye el HTML del servidor por la app viva en la misma tarea (sin parpadeo). No adopta los nodos existentes, así que el cliente vuelve a renderizar: se gana el contenido visible antes y el SEO, no el ahorro de trabajo de una hidratación completa. Tampoco hay streaming.

// servidor (Node)
import { renderPage } from '@duvanjamid/angelite/tools/ssr.mjs';
import { provideRouter } from '@duvanjamid/angelite/lite';

const html = await renderPage(App, {
  shell: '<!doctype html><body><!--app--><!--state--><script type="module" src="/client.js"></script></body>',
  url: req.url,                                            // path + query
  setup: () => provideRouter(routes, { mode: 'history' }),  // se ejecuta con el DOM ya disponible
  ready: async app => { await app.usuarios.settled; },       // espera a tus datos
  state: { usuarios }                                      // llega al cliente como window.__STATE__ (con < escapado)
});

// cliente
import { hydrate } from '@duvanjamid/angelite/lite/hydrate';
hydrate(App, document.getElementById('app'));

DevTools y herramientas de build

DevTools. enableDevtools({ panel: true }) (lite/devtools) añade window.__ANGELITE__ (tree(), inspect(el), state(instancia), set(instancia, 'campo', valor)) y un panel flotante con el árbol de componentes y el valor de sus señales. Es un inspector básico: no hay línea de tiempo ni edición desde el panel.

Vite. tools/vite.mjs compila *.ng.html con recarga al editar y los mismos avisos que el plugin de esbuild. Editor. angelite-check (o node tools/check.mjs src --members auto) lista los problemas como archivo:1: mensaje, que el editor entiende como errores; no hay autocompletado de plantillas.

// vite.config.js
import angelite from '@duvanjamid/angelite/tools/vite.mjs';
export default { plugins: [angelite({ components: ['ui-button'], members: 'auto', check: 'error' })] };

// package.json: "scripts": { "check": "angelite-check src --members auto" }

Pipes

Incluidos: uppercase, lowercase, titlecase, json, number, percent, currency, slice, date. Un pipe es solo una función:

Servicios

inject(Clase) devuelve una instancia compartida (se crea al primer uso). Con provide(Clase, valor) puedes sustituirla, por ejemplo en tests. Si un componente declara providers, el servicio es suyo y de sus descendientes (cada instancia del componente tiene el suyo): { provide: Api, useClass | useValue | useFactory } o simplemente la clase.

Router

Router por hash: parámetros (:id), comodín **, rutas anidadas (children + un <router-outlet> dentro del componente padre), guards (canActivate), carga diferida (load) y redirectTo. Un guard recibe { path, params, route } y devuelve true (pasar), false (quedarse donde estabas) o una ruta (redirigir); puede ser asíncrono. Una navegación nueva cancela la anterior si sigue esperando. (No lo activo en esta página para no pisar sus anclas.)

const { component, mount, provideRouter, router, inject } = AngeLite;

class Home {}
component(Home, { template: `<h2>Inicio</h2>` });

// padre con su propio outlet
class Admin {}
component(Admin, { template: `<nav>Administración</nav><router-outlet></router-outlet>` });
class AdminHome {} component(AdminHome, { template: `<h3>Resumen</h3>` });
class AdminUser { id = () => router.params().id; }
component(AdminUser, { template: `<h3>Usuario {{ id() }}</h3>` });

class NotFound {} component(NotFound, { template: `<h2>404</h2>` });

const soloAdmin = async ({ path }) => (await sesion.esAdmin()) || '/login';   // true | false | ruta

provideRouter([
  { path: '/', component: Home },
  { path: 'admin', component: Admin, canActivate: [soloAdmin], children: [
    { path: '',          component: AdminHome },
    { path: 'users/:id', component: AdminUser }
  ] },
  { path: 'informes', load: () => import('./informes.js') },      // se descarga en la primera visita
  { path: 'viejo',    redirectTo: '/' },
  { path: '**',       component: NotFound }
]);

class App {}
component(App, {
  template: `
    <nav><a routerLink="/">Inicio</a> <a routerLink="/admin/users/42">Usuario 42</a></nav>
    <router-outlet></router-outlet>`
});
mount(App, document.getElementById('app'));

Query y datos. router.query() devuelve ?pagina=2 como { pagina: '2' }; resolve: { usuario: ({ params, query }) => … } carga datos antes de pintar la página (si falla, te quedas donde estabas) y router.data().usuario los entrega. Modo history: provideRouter(rutas, { mode: 'history', base: '/app' }) usa rutas reales (el servidor debe devolver la misma página para todas); los clics en routerLink navegan sin recargar y una dirección compartida como /app#/ruta aterriza en /app/ruta. Las rutas //otro-sitio nunca salen del sitio. router.navigate('/x', { replace: true }) sustituye la entrada del historial.

Por defecto el router usa el modo hash, que funciona en cualquier hosting estático.

Herramientas: tipos, tests, avisos y chequeo de plantillas

TypeScript. El paquete trae sus .d.ts (comprobados con tsc en el CI): signal<T>, input<T>, output<T>, viewChild<T>, Route, RouteGuard, OnInit/OnDestroy/OnError… Funciona igual con JS y con TS.

Tests. @duvanjamid/angelite/lite/testing monta un componente en el documento y te da lo básico para interactuar con él:

import { render, cleanup } from '@duvanjamid/angelite/lite/testing';

afterEach(cleanup);

test('suma', async () => {
  const t = render(Counter, { props: { start: 5 }, provide: [[Api, apiFalsa]] });  // props = inputs; provide = servicios
  t.click('button');
  await t.flush();                                  // espera a que las señales lleguen al DOM
  assert.equal(t.text('output'), '6');
  t.type('input', 'Ada');                           // escribe y dispara input + change
});

Avisos de desarrollo. enableDevWarnings() (solo en desarrollo, antes de montar) avisa de lo que de otro modo falla en silencio: un [prop] que el componente no declara como input, claves repetidas en @for, un elemento desconocido o un módulo opcional (portal, defer) sin importar.

Chequeo de plantillas al compilar. El compilador AOT avisa (o falla, con check: 'error') si una plantilla usa un elemento desconocido, un pipe que no existe o —si le das la lista, o members: 'auto' para leerla de la clase vecina— un nombre que el componente no tiene. No comprueba tipos.

aotPlugin({ components: ['ui-button'], members: 'auto', check: 'error' })

// counter.ng.html: <p>{{ cuenta() }}</p>      →  error: "cuenta" is not a member of the component

Precompilar plantillas (opcional)

Por defecto Lite compila las plantillas en el navegador: un solo script, sin build. Si te importa cada KB, puedes convertir las plantillas en JS durante el build y enviar solo el runtime (sin parser de expresiones ni compilador): unos ~6 KB gzip en total para una app real, algo menos que Preact (6,2 KB).

// counter.ng.html
<button (click)="inc()">Clicks: {{ count() }}</button>

// counter.js
import { signal, component, mount } from '@duvanjamid/angelite/lite/runtime';
import aot from './counter.ng.html';              // compilada por el plugin

class Counter { count = signal(0); inc() { this.count.update(n => n + 1); } }
component(Counter, { aot });                       // en lugar de template
mount(Counter, document.body);

// build (esbuild)
import { aotPlugin } from '@duvanjamid/angelite/tools/aot.mjs';
esbuild.build({ entryPoints: ['counter.js'], bundle: true, minify: true, plugins: [aotPlugin({ components: ['ui-button'] })] });

También hay una CLI: node tools/aot.mjs plantilla.html salida.js --components ui-button,ui-card. El código generado se comprueba en los tests: una plantilla precompilada produce exactamente el mismo DOM que la compilada en el navegador. Los pipes integrados son opt-in en este modo: import '@duvanjamid/angelite/lite/pipes' o registra los tuyos con registerPipe.

La herramienta usa jsdom solo en tiempo de build. En producción no se carga nada de ella.

Seguridad

El modelo es simple: las plantillas son código tuyo; los datos que muestras no son de fiar. Lite está hecho para que un dato no se convierta en HTML, script o URL peligrosa por accidente.

  • {{ valor }} siempre se inserta como texto.
  • Las URL en href, src, action… solo dejan pasar http(s), mailto, tel, sms, ftp y rutas relativas; lo demás pasa a unsafe:… y avisa en consola.
  • [innerHTML] solo pinta HTML envuelto en trustHtml(); cualquier otro valor se inserta como texto.
  • [onclick], [srcdoc] y bindings sobre <script>/<base>/<link> son un error de compilación.
  • Las expresiones nunca reciben window ni document, vengan de donde vengan.
  • Sin eval ni new Function: funciona con una CSP sin unsafe-eval, y soporta Trusted Types.
import { signal, trustHtml, trustUrl } from '@duvanjamid/angelite/lite';

html = signal(trustHtml(DOMPurify.sanitize(comentario)));   // tú te haces responsable: sanea antes
link = signal(trustUrl('whatsapp://send?text=hola'));       // esquema propio permitido a propósito

// CSP recomendada
// Content-Security-Policy: default-src 'self'; script-src 'self'; require-trusted-types-for 'script'; trusted-types angelite

El sandbox de expresiones es defensa en profundidad, no un límite de seguridad: nunca compiles plantillas que incluyan datos de usuario. En producción precompila con tools/aot.mjs. Más detalle en SECURITY.md.

Diferencias con Angular

Es "homólogo", no un clon. Lo que cambia a propósito para mantenerlo pequeño:

AngularAngeLite Lite
Decoradores + TypeScript + compiladorcomponent(Clase, meta) en JS plano (también hay Component(meta) como decorador si tu toolchain los soporta)
Zone.js / detección de cambiosSeñales: solo se actualiza lo que depende de ellas. Mutar una propiedad normal no repinta; usa signal.
@Input() / @Output()input() / output()
[(ngModel)]="prop"[(ngModel)]="signal" (la señal debe ser escribible)
Asignaciones en plantillas ((click)="x = 1")No: (click)="x.set(1)"
@angular/forms, HttpClient, @angular/localize, animaciones, SSRMódulos opcionales: forms, http, i18n, animate y tools/ssr.mjs. Más pequeños y con menos funciones (sin FormBuilder, validadores asíncronos, ng extract-i18n, @angular/animations con estados, hidratación incremental). La tabla comparativa dice qué falta.
@defer, viewChild(), providers, children/canActivate/loadComponentSí, con la misma idea: @defer, viewChild(), providers, children/canActivate/load

Seguridad: la interpolación escribe siempre texto. Si enlazas [innerHTML] es tu responsabilidad sanear el contenido.
